/pop means puppet/doll in the Dutch language/ 🇳🇱

🚧 work-in-progress

pop-test simplifies end-to-end testing by providing a powerful orchestration tool and expressive language for your applications and their dependencies.

Define your test scenarios in a DSL (YAML, TOML or JSON) and automate the spinning up (and down) of complex environments involving multiple programs, databases, and services, executing comprehensive tests with ease.

pop-test is built with Rust, enhancing safety, performance and reliability, with a modern and accessible code-base.

** The DSL (Domain Specific Language)

Here follow some examples of pop-tests.

In this example we spin up a REST API written in Scala, with SBT, and poll its ~/health~ endpoint for 60 seconds or until healthy. Then we perform some checks on certain HTTP endpoints.

#+begin_src yaml
pop_test:
  pop_services:
    - id: "green-energy-mix"
      dir: "$HOME/Ontwikkeling/Werk"
      base_url: "http://localhost:50000"
      start_cmd_args:
        - 'sbt "greenEnergyMix/run"'
      env_vars:
        NATIONAAL_ENERGIE_DASHBOARD_TOKEN: "0027809ce9"
      health_check:
        path: "/health"
        patience_seconds: 90

  pop_checks:
    - check_url: "/api/v1/forecast"
      service_id: "green-energy-mix"
      json_body_patterns:
        - pattern: '"meta""forecastDate"'
          condition: '!= ""'
        - pattern: '"data"[0]"load"'
          condition: "> 0"
        - pattern: '"data"[0]"solar"'
          condition: ">= 0"

#+end_src
